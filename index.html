GOVERNED AI EXECUTION

Governed infrastructure for AI agents that act on real systems.

AI can produce a result. Baranes is about the harder boundary: deciding what may become real system state, executing it inside bounded authority, and preserving evidence of what actually happened.

RepoOps is the first concrete Baranes domain used to explain the model: repository work moves from bounded candidate execution to controlled canonical adoption.

THE PROBLEM

Agent output is not the same as authorized system state.

Modern agents can edit files, run tools and propose changes. Once those actions touch repositories or operational systems, the important questions become authority questions.

Who authorized this effect? What exactly was in scope? Was the result only candidate state, or did it become canonical? What evidence supports the final state?

BARANES MODEL

A governed path from intent to effect

  1. IntentUnderstand the requested work and bind the relevant context.
  2. AdmissionDetermine what is allowed and under which constraints.
  3. Bounded executionProduce candidate work without silently expanding authority.
  4. VerificationCheck actual resulting state using evidence appropriate to the affected domain.
  5. Canonical effectAdopt only through the governed domain boundary.
FIRST DOMAIN

RepoOps makes the boundary concrete.

Repository work is a useful first proving ground because agent-generated changes can be valuable while still requiring explicit separation between candidate engineering and canonical repository state.
